OnePlatform exposes a unified HTTP API across 9 microservices, all accessible through
the Gateway at a single host.

## Authentication

All API endpoints (except `/api/v1/auth/login`, `/api/v1/auth/register`, and
`/api/v1/auth/bootstrap`) require a Bearer token:

```http
Authorization: Bearer <access_token>
```

Obtain a token via `POST /api/v1/auth/login` or the `op auth login` CLI command.
API keys are also accepted with the `ApiKey <key>` prefix.

## OpenAPI Specifications

The live OpenAPI spec is available from a running gateway:

| URL | Description |
|-----|-------------|
| `GET /api/v1/openapi.json` | Tenant-specific combined spec (requires auth) |
| `GET /api/v1/openapi/base.json` | Static base spec (no tenant overlay, public) |
| `GET /api/v1/openapi/{service}.json` | Per-service spec |

Download the merged spec for use with code generators:

```sh
# With authentication (includes your tenant's entity type routes)
curl -H "Authorization: Bearer $(op auth token)" \
  http://localhost:3000/api/v1/openapi.json > openapi.json

# Without authentication (generic routes only)
curl http://localhost:3000/api/v1/openapi/base.json > openapi-base.json
```

Generate a TypeScript SDK from the spec:

```sh
op sdk generate-types
```

## Error format

All error responses follow the same envelope:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Human-readable description",
    "details": {}
  }
}
```

Common codes: `UNAUTHORIZED` (401), `FORBIDDEN` (403), `NOT_FOUND` (404),
`VALIDATION_ERROR` (422), `INTERNAL_ERROR` (500).
